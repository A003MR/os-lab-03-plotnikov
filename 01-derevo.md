# Задание 1. Дерево процессов

## Пробили цепочку
С помощью команд `echo $$` и `ps -o pid,ppid,user,cmd -p` мы раскопали всю матрешку процессов (снизу вверх):

| PID | PPID | Юзер | Команда |
| :--- | :--- | :--- | :--- |
| 3543 | 3480 | admin | /usr/bin/bash (моя текущая оболочка) |
| 3480 | 3443 | admin | /usr/libexec/ptyxis-agent --socket-fd=3 --rlimit-nofile=1024 |
| 3443 | 2123 | admin | /usr/bin/ptyxis --gapplication-service |
| 2123 | 1 | admin | /usr/lib/systemd/systemd --user |
| 1 | 0 | root | /usr/lib/systemd/systemd |

## Отвечаем на вопросы
**Кто в корне дерева и почему у него нет родителя?**
Бро, в самом корне сидит `systemd` с PID 1. У него нет родителя (PPID = 0), потому что его запускает само ядро Linux при старте системы. Все остальные процессы в системе — это его потомки.

**Сколько всего процессов и почему большинство в состоянии S?**
В системе крутится 323 процесса (вывод `ps aux | wc -l`). Большинство висят в стейте `S` (Sleeping / Ожидание). Это нормально: процессы не должны постоянно грузить процессор. Они дремлют и просыпаются только тогда, когда происходит какое-то событие (нажатие клавиши, прилетел сетевой пакет и т.д.).
